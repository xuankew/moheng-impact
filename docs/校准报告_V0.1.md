## 4. 校验方法

1. **直连 Handler 召回**：变更符号与 API Handler 求交集，检查对应 API 是否全部进入影响列表。三集合计 77/77。
2. **路径不变量**：逐条路径检查
   - `depth == edges.size()`；
   - 起点为 `changedKey` 或首条边的另一端；
   - 末条边类型为 `EXPOSES_API` 且指向 `API:` 节点；
   - 不存在自环。
   三集合计 1,005 条路径，0 违规。
3. **调用边核对**：对每条 `CALLS` 边，读取 caller 所在源码，确认存在 callee 简单名调用点。三集合计 479/479。
4. **未产生符号的文件复核**：C 集中 9 个非测试 Java 文件未产生变更符号，逐个人工核对，差异均为 import、注释或空白，无代码逻辑变更；另有 2 个测试文件因默认不分析 `src/test/java` 而跳过。
5. **结构化端到端**：`AnalysisEngineEndToEndTest` 在临时 Git 仓库中执行「两次提交 → diff → 符号 → 调用链 → API → 风险」，断言路径边方向、等级与分数。

## 5. 校准中发现并修复的问题

### 5.1 嵌套类型未进入符号与调用图

Spoon 的 `CtModel.getAllTypes()` 只返回顶层类型。校准集 C 中一个包含大量嵌套枚举的常量类发生构造器与字段变化，却没有产生任何变更符号。

修复：`SpoonContext` 递归展开 `getNestedTypes()`，按身份去重后建立类型、符号、继承与调用关系。新增 `NestedTypeTest` 回归测试。

修复前后（同一大发布差异）：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 索引类型 | 1,690 | 1,919 |
| 符号总数 | 13,854 | 15,597 |
| Lombok 解析调用 | 12,497 | 13,940 |
| 变更符号 | 661 | 716 |
| 受影响 API | 195 | 202 |

该修复同时覆盖嵌套类中的 Controller、DTO 与工具方法，是本次校准的主要精度提升项。

## 8. 结论

V0.1 的变更符号、反向影响、API 映射与风险链路在三个规模的内部变更集上稳定运行，结构不变量与调用点核对全部通过；嵌套类型缺口已修复并加入回归测试。剩余风险集中在动态调用边界与业务语义精确率，需在后续版本引入人工金标准与运行时证据。
